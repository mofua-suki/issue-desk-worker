# hostdによるWorker版の反映

配信の登録はServer側の操作で、各PCのWorker切替はその後に各PCのhostdが行います。Intakeの `update.sh --intake-now` はServerの入替間隔の判定を省きますが、Worker登録の条件付きの60分待機やhostdの安全条件を省きません。登録が済んだことを確認してから各PCで次を実行します。

```sh
hostd update-now --config /絶対パス/hostd/config.json --wait 10m
```

NASではホストの既存設定を変更せず、コマンドを `env -u GODEBUG hostd update-now ...` で起動します。設定と専用資格情報は既存hostdのものを使い、内容を表示しません。周期処理と同じ実行ロックを使うため、実行中なら完了を待って再実行してください。installの強制切替は使いません。

待機中はlazyの空き、heartbeat、実行中・公開中件数を表示します。busyの間はdrainを維持し、新しい実装の検出やdrain期限到達では解除して切り替えません。待機時間の経過や取消し後の状態は通常周期で再開できます。ready確認中に期限を迎えた場合も次回に確認します。

待機中の件数は取得できたheartbeatの値です。件数が欠ける場合は「件数未確認」と表示します。

| 理由 | 表示文 | 終了コード |
| --- | --- | --- |
| lazy待ち | lazyの空きを待っています（実行中 N、公開中 N）または（件数未確認） | 2（期限・取消し時） |
| heartbeat待ち | heartbeatを待っています（実行中 N、公開中 N）または（件数未確認） | 2（期限・取消し時） |
| 仕事の完了待ち | 仕事の完了待ち: 実行中 N、公開中 N | 2（期限・取消し時） |
| 待機期限 | 待機期限に到達しました | 2 |
| 取消し | 待機を中止しました | 2 |
| 実行ロック中 | 実行ロック中です | 2 |
| 新しい実装 | 新しい実装を検出しdrainを解除しました | 2 |
| drain期限 | drain期限に到達し解除しました | 2 |
| drain喪失 | drainを確認できず切替を中止しました | 2 |
| 別の指示 | 別の指示の完了を待っています | 2 |

待機中の表示自体は終了を意味せず、期限時には最後の待ち理由も表示します。

終了コードは、0が完了または操作不要（同一版、配信なし、pin、failedTags、成功結果の再送）、1が失敗（digest不一致、ready期限切れによる復旧、更新失敗、中断更新の復旧、失敗結果の再送を含む）、2が待ち・未完了（ロック中、期限、取消し、drain解除など）です。通常timerの正常な待ちは成功です。通常周期の`hostd`と、serviceが周期の前に呼ぶ`hostd --check`も、ロック中は「実行ロック中です」と表示して0で終えます。設定と資格情報の誤りは、ロックの確認より前に1で終えます。

即時反映中は実行ロックを保持するため、通常周期のapps・readers・liveChecksはその間実行されません。更新中のserviceを停止したりロックファイルを削除したりせず、完了を待ってから再実行してください。

通常周期は完了後5分のままです。短縮すると各PCの定常的な通信・起動が増えるため、急ぐ場合だけ有限の待機時間で即時反映を使います。Workerのheartbeatは従来の3分周期です。
