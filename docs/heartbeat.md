# 実行PCの生存・負荷・受け取り保留

実行PCは起動検査後と3分周期に `PUT /api/v1/hosts/<workerId>` へ状態を送る。受付のPC一覧、CLI版の要対応、負荷による配布抑止、hostdの退避確認が同じ値を使う。

| 項目 | 生成元と意味 |
| --- | --- |
| revision / imageRevision | 実行バイナリへ埋めた公開commit。開発時に確定できなければnull。 |
| cliVersions | Codex・Claudeの実版、imageの固定定義、検査時刻（Unixミリ秒）、不一致の理由。版の相違は注意として残す。 |
| load | Linuxの実測値。読めなかった項目は省略し、全欠測ならnull。実測0は0のまま送る。 |
| busy | 実行・結果報告待ち・監視依頼の処理がある。 |
| implementing | 実行中のうち公開工程以外と取得・結果報告の確定待ち。 |
| publishing | 固定テスト・レビュー・公開・マージ・配置の実行中件数。監視依頼の処理も退避前に数える。 |
| capabilities | 実行OS、設定された実行先、担当リポジトリ、監視アカウントの区分。 |
| ready / checks | readyは起動検査の成功かつ取得が停止・一時失敗中でないこと（設定の版が変わり再起動を待つ間も取得の停止に当たる）。checksのat・ok・itemsは実施済み起動検査を表し、settingsVersionは検証して使用中の運用設定の版を表す。設定の読取や検証に失敗した場合は使用中の版を維持する。一時的な取得失敗中はready=false・checks.ok=trueとなり、実行中の件数も報告し続ける。取得が回復すればreadyを戻す。 |
| capacity | 受付の担当表で定めた実行枠。 |
| intakeHold | このPCの実行環境・実行先利用上限による受け取り保留。理由が外れればnullへ戻す。 |

運用設定は約1分周期で確認し、検証後にAI呼び出しへ反映する。providerDisableを含む変更は反映まで通常最大約1分かかり、通信やheartbeat送信が遅れた場合はさらに遅れる。依頼（手動マージ・全体テストなど）を同期で処理している間は確認が進まないため、その処理の終了まで遅れる。設定の版が変わった後は再起動まで反映しない（再起動後の設定で使う）。実行中のAI呼び出しには開始時の設定を使う。

負荷のサンプルは5秒周期で、生存の送信周期とは独立する。CPUはuser・nice・sys・idle・irqの差分から直近60秒を測り、65秒まで保持する。1分未満、最後のサンプルから5秒超、時刻やカウンターの逆行、CPU数の変化はCPU欄を送らない。5分後の報告でも5分全体を平均しない。

loadAverage1mは `/proc/loadavg` の1分値（読取失敗時はsysinfo）、logicalCpuCountはCPU affinityとcgroupの上限で制限されたCPU数。freeMemoryMBは固定Node/libuvと同じMemAvailable優先、未取得または0ならsysinfoのfreeramを使う。freeDiskMBはruntimeDirの利用可能ブロック数×ブロックサイズ。それぞれ1024² bytesで割る。読取失敗を0に置き換えず、予約ブロックは含めない。GPUは `nvidia-smi` が利用できる場合は先頭GPU、そうでなければ読み取り可能なAMD DRMの先頭GPUから使用率と専用VRAMの空き（MiB）を取得する。AMDでは `gpu_busy_percent` と `mem_info_vram_total`・`mem_info_vram_used` を使用する。対応しない項目や取得失敗は省略し、共有メモリーを空きVRAMとして扱わない。GPU取得の待機は最大100ミリ秒で、遅延中も他の負荷を送る。

明示的な実装CLIのプラン利用上限だけを保留へ記録する。正常回答の本文や一時的な429をプラン上限と扱わない。CLIの再開時刻が未来7日以内なら採用し、確かめられなければ30分後を見込みとして残す。ジョブを自動再試行したり、上限を理由に実行先を自動変更したりしない。レビュー側の上限だけで新規実装を止めない。

保留は `runtimeDir/control/host-holds.json` に原子的に保存する。ファイルが無ければ保留なしで始める。固定テストの子プロセスが合格0件で作業ツリー外のEPERM/EACCESにより失敗した場合も環境保留へ記録し、実装AIへ修正を頼まず作業を保存して停止する。環境保留は起動時または正規の再検査で実隔離が通った時点で解除し、永久保留としない。未実施の検査や不正な保存内容を成功・保留なしに置き換えない。

旧版Workerへの巻き戻しでは、旧版が保留を保存すると `claudeApiKeyHold` 欄が消える。引き取りを停止し、実行・送信の完了とWorkerの停止を確認してから `runtimeDir/control/host-holds.json` を安全な場所に保全する。APIキーの利用上限が解除されるまで旧版でClaudeの仕事を取得しない。新版へ戻す際はWorker停止中に保全した欄の期限を確認し、必要な保留を復元してから起動する。保全した状態には運用情報が含まれるためアクセスを制限する。

更新後のhostdは、新しいrevisionの新鮮なheartbeatで実行中件数が正しく報告されている間、ready=falseでも確認期限を延長する。仕事の完了後は通常のready確認期限を適用する。
