# レビュー件数の集計

対象期間・対象ジョブを決め、各ジョブの最新の完了結果 `reviewCounts` を1件ずつ集計する。`full`、`delta`、`skipped` の合計をそれぞれ F、D、S とし、N = F + D + S が正なら比率は F/N、D/N、S/N。N が0なら比率は未定義。`skipped` はレビュー省略、`delta` は差分レビューであり、比率は実時間や費用の削減率ではない。

選択した各ジョブの完了結果オブジェクトをJSON配列にまとめ、`go run ./cmd/review-counts < results.json` で集計できる。出力の `jobs` は件数を集計したジョブ数、`missing` は `reviewCounts` がない結果の数、`counts` は種別ごとの合計、`ratios` は種別ごとの比率である。合計が0の場合の `ratios` は `null`。ジョブの選択と重複排除は入力を作成する際に行う。不完全または負の件数はエラーになる。

件数はジョブ単位の累計スナップショットなので、同じジョブの再送や複数の結果を合算しない。期間中の増分を求める場合は同じジョブの期間前後のスナップショットの差を使い、新規ジョブは開始時を0とする。途中からしか観測できないジョブや結果が欠落したジョブは区別して集計対象・欠損数を報告する。`reviewCounts` がない旧結果をゼロとみなさない。`reviewRounds` は直近20件に制限されるため累計の代用にはならない。

旧形式の保存レコードは、初回保存または結果生成時に残存する `reviewRounds` から件数を初期化する。旧実装が既に切り詰めた履歴は復元できず、この時点の残存履歴が起点となる。移行をまたぐ累計や比率は過少になり得るため、旧レコードを区別し、集計期間と欠落の可能性を結果に添える。
