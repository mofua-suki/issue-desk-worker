# 継続時の作業ツリー確認

Workerは、継続に必要なコミットを含む作業ツリーを確認してからAIを起動する。検査は世代初期化、実行回数の再計算、未回答の開始の回収、使用量送信より前に行う。同じjobの再開と、job IDが変わる継続の両方を対象とする。

## 継続元の特定

受付が配布したhead・PR、現在jobの保存head、同一repo・Issueの別jobのjournalから必要な先頭を解決する。別jobについては記録された枝の遠隔参照とローカル参照も照合する。job ID・枝名の数字やjob間のgenerationの大小から、どの成果物が必要かを推測しない。

PRは番号、head/baseのrepo、base枝、記録された枝との対応を検査する。候補が複数ある場合は、全候補が一つの祖先関係に収まるときだけ必要先頭を定める。参照の欠落、取得失敗、比較不能、分岐で必要先頭を定められない場合は保留する。

現在枝の存在、fetch成功、ファイル名の存在、受付のcontinuationのpresent/pendingだけを、以前の成果物を含む証拠にしない。コミットの実在と、実際の作業ツリーのHEADに対する祖先関係を検査する。generationが正で照合headを得られない場合はAIを起動せず保留する。コミット前の停止でjournalにheadがなく遠隔枝もない場合も、別PCの未公開成果物の有無は判定できないため同様に保留する。旧成果物を放棄して基点から再試行するには明示的なretryFromBase指示が必要である。同generationでも、開始済み回数や停止・保留・失敗の状態を持つ再開は継続として検査する。

## 作業ツリーと状態の保持

必要先頭が現在の作業ツリーに含まれていない場合は、cleanで安全にfast-forwardできるときだけ追従する。分岐した作業をresetで捨てたり、自動で統合したりしない。追従前にleaseと中断状態を確認し、古いツリーへのテスト・レビュー承認を無効化して保存する。追従後はOpenの禁止ファイル検査と実HEADの包含検査を行う。

保留は新しい実装開始として数えない。既存の結果、使用量、未回答の開始、報告補完の記録を保持し、必要に応じて以前の結果・レビュー欄へ証拠を残す。受付が保留の受領を確認した後は、保存した工程と結果に応じて再開する。

journalの`continuationBranch`は、前generationまたは停止済みjournalから採取した現在jobの枝を表す。nilは未採取、空文字は利用できる継続元の枝がない状態を表す。現generationの新規現在枝だけの記録を継続元とせず、保留の保存やjob ID変更によってその枝を以前の成果物の証拠へ昇格させない。headまたはPRが記録されれば、それらを独立に照合できる。

## retryFromBase

旧成果物の放棄は、現generationの明示的なretryFromBase指示とその適用印に従う。適用印だけで通常継続を検査対象外にしない。retryの初期化ではcontinuationBranchを未採取へ戻し、同一repo・Issueの放棄対象をjob ID・generation・branch・head・PRの組でjournalの`discardedContinuationSources`へ保存する。次generationや別jobでの通常継続でも、その組に一致する記録は再び必須候補にしない。新しいjobや記録の更新まで除外を広げず、retry成果物自身の包含を確認する。

旧枝を指す配布情報を除外する場合も、retry自身のjournalにあるhead・PRは検査する。retry枝を指す配布PRは保存PRと同番号でも解決し、先頭を包含できなければAI起動前に保留する。枝の指定がない配布PRはretry枝との対応を検査する。保存PRがある場合、PR先頭の包含とは別に公開済み枝の遠隔参照の保護も適用する。

## 保留結果と確認項目

保留は`held`、`holdReason=review_held`で返し、`view.continuationHead.cause`に固定の理由コードを載せる。`requiredHead`は配布されたHeadSHAが有効な形式の場合にその値を示し、すべての解決済み候補の一覧ではない。`checkedHead`と`source`は失敗した照合対象とその出所を示し、対象を特定できない場合は空のheadと未確認の出所を示す。要約には理由コード、不足内容、再開条件を含める。GitやPR取得の未検査の出力・エラー本文、不正なheadの原文を保留理由へ流さない。

運用で確認する値は、配布descriptorのjob・repo・Issue・generation・branch・headSha・pr、起動前journalの対応項目とretry指示・適用印、当時の照合参照と実HEAD、実行プロセス版である。受付の配布・保留記録、Workerの照合結果、AI呼出しを区別する。短い終了時間や保留の要約だけをAI呼出しの証拠にせず、後から取得した枝の先頭を当時の値として扱わない。
