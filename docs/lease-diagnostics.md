# leaseの診断

leaseの期限切れ・所有権喪失・延長拒否・応答不一致と、範囲重複による解放は `lease_diagnostic` の1行ログに仕事ID・generation・epoch・UTC時刻・固定理由・工程・工程別の観測時間（ミリ秒）を記録する。工程の `implement_report` はimplementing、`test_report` はtestに含める。未観測の工程はnullで、実際に観測した0とは区別する。追跡開始前に工程が進んでいた場合や停止・再開間は不明として `incomplete=true` とし、再開前後の観測区間だけを合計する。同じepochの再開でも空白時間を加えず、別epochまたは世代の時間は別にする。障害時刻以降に保存された工程も、その障害時点の時間に加えない。

診断は `runtimeDir/state/lease-diagnostics/job-<仕事ID>-*.json` に原子的に保持し、後に新しく作成する結果のsummaryの本文を優先し、残りの字数に収まる場合は新しい順の診断と読取可能な保持件数を載せる。読取不能な診断はログで通知し、結果作成を妨げない。範囲解放時はローカルに保存する結果にも載せる。すべての診断はローカルに残り、再送時も送達済みと決めつけない。すでに保存した未送信の最終結果は変更しないため、その結果だけが送達される場合、または別の実行PCで再配布された場合は診断がsummaryに届かない。受付側による旧epochの受理は保証されず、診断専用の収集経路は既存契約にないため、必要な照合は当該PCの保持ファイルと1行ログで行う。

照合は当該PCでログと保持ファイルをアクセス制限した場所に集め、秘匿処理後の対応する `lease_diagnostic` 1行と `state/lease-diagnostics/job-<仕事ID>-*.json` をJSONとして読む。秘匿処理では両方の同じ識別子を同じ仮名に置き換え、照合に必要なキーと値の関係を保持する。複数件がある場合はjob・generation・epoch・atとreasonで候補を対応付け、重複や候補なしも記録する。各組について `job`・`generation`・`epoch`・`at`・`reason`・`stage`・`duration_ms`・`incomplete` を比較し、`duration_ms` は各工程のキーと値まで比較する。nullを0に変換せず、値の不一致、キーや対応レコードの欠測、JSONの破損や読取権限不足などの読取不能をそれぞれ明示する。欠測や読取不能を一致と判断しない。

実際の再配布原因、旧epoch診断の受付受理、別PCへの再配布時の診断の行先は別々に実機の秘匿済み記録で確認する。
